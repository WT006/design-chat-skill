# 完整对话测试

这里有三位模拟用户：设计个人网站的初学者、讨论收藏工具架构的独立开发者、调整已有读书活动方案的组织者。每段通常 6–10 轮，模拟用户根据助手的真实回答追问、质疑、补充限制或作决定。不会强制最后谈成。

## 手动运行

**修改 skill 不自动触发测试。** 用户明确要求时才运行；没有定时任务、文件监听或提交钩子。

```bash
python3 evals/run.py
```

需要 Python 3.9+、Git、已登录且支持所用开关的 Codex CLI。运行会使用模型额度。默认两个对话并行；`--jobs 3` 可调整并行数，`--timeout 240` 控制每次模型调用的超时。

首次运行同时测试 HEAD 版本和当前工作区版本。后续自动选择最近一次完整运行，左边复用其候选版对话，右边运行当前版本；这是手动运行之后的基线选择，不是自动触发。也可以指定：

```bash
python3 evals/run.py --baseline <修改前的提交>
python3 evals/run.py --previous <某次运行目录>
```

用例、模拟用户提示或执行方式改变时，不复用旧对话；改用保存的上一版 skill 快照，在相同的新条件下重新运行双方。只跑一段时用 `--cases personal-website`、`bookmark-architecture` 或 `reading-club-revision`，这样的结果不会成为下一次全套测试的基线。

## 固定输出目录

- `evals/results/html/YYYY-MM-DD.html`：给用户看的完整对话，左边上次、右边这次。日期采用 Asia/Shanghai。同日重跑更新当天文件。
- `evals/results/runs/<日期与时间>/`：每次独立存档，保留该次的同名 HTML 和全部原始数据。
- `evals/results/latest.json`：最近一次完整的三段对话运行位置，仅供下次手动测试选择基线；不是自动任务。

HTML 只显示场景名称、双方用户发言与助手最终回复；不额外生成 Markdown 报告。两边的对话沿各自真实回答展开，因此长度和问题措辞可能不同。读整个讨论过程，不把左右同一高度当作同一个问题。

需要重新生成已保存运行的 HTML，无需调用模型：

```bash
python3 evals/run.py --render-only <运行目录>
```

全部运行数据默认不提交 Git。skill 快照保存为 `snapshots.json`，避免历史版本被技能发现机制重复加载。`cases.json` 保存用户背景和关注点，`engine.json` 保存执行器和模拟用户提示，`metadata.json` 保存版本、模型配置、日期及运行状态。每段对话保留用户生成记录、助手回复、工具事件和实际文件差异，便于必要时复查。

## 三段对话覆盖什么

| 对话 | 用户的主要经历 | 观察重点 |
| --- | --- | --- |
| 个人网站 | 看整体框架 → 表达偏好 → 追问与修改 → 梳理 → 确定首页 → 聊照片 | 建议的具体程度、回应空间、模糊认可、确认后整合零散需求 |
| 收藏工具架构 | 理解本地与云端 → 提出推断 → 补充维护限制 → 问备份迁移 → 局部拍板 → 聊标签搜索 | 解释和取舍、纠正误解、调整方案、批准范围、话题控制 |
| 读书活动修订 | 读取已有设计 → 讨论新需求 → 暂缓修改 → 切去报名 → 总结 → 回头确认部分修改 | 连续上下文、新旧冲突、跳题回退、未定事项、保留已有决定 |

这些是人物的目标与关注点，不是逐轮固定台词或必须完成的剧情。模拟用户只看到自己的背景、需求和当前对话，看不到 skill 规则、版本标签、观察重点或文件检查结果。助手只看到实际对话、初始项目资料和被测 skill，看不到用户的隐藏意图和未来计划。开场相同，后续各自自然发展。

## 范围与局限

助手与用户模拟各用独立临时目录。每段对话的项目文件跨轮保留，每轮传入真实历史；每轮 CLI 会话重新启动，因此不等同于桌面聊天的完整运行环境。调用忽略用户配置，关闭 hooks、插件和应用，并跳过宿主技能发现。助手使用 workspace-write 沙箱；模拟用户使用 read-only 沙箱且被要求不调用工具。真实项目不参与文件操作。

默认使用 CLI 默认模型，未固定型号；可以用 `--model <型号>` 为双方和两个版本显式指定同一个模型。修改模型配置时重新运行双方。环境与输出具有随机性，动态用户也会影响后续路径，不能把一次差异全部归因于 skill。若有疑问可以用同一基线重复运行，保留所有结果，不挑选最好的一次。

不让另一个模型替用户给回复打分。文件变化仅保留为辅助证据，不通过固定词语判断动态发言是否授权写入。最终由用户直接阅读 HTML 判断有没有更好。
