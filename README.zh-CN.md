# Talk to Plan

[English](README.md) | **中文**

由人主导的设计讨论 skill。与 AI 一起梳理想法，把明确认可的决策沉淀为清晰的设计文档。

## 为什么做这个 skill？

- **你是否被 AI 连续追问弄得很累？** 本想一起探讨思路，却变成了回答一长串细节问题。
- **你是否还没想好，AI 就替你定了方案？** 随口提出的想法，还没认可就被写成了正式需求。
- **你是否聊了很久，还得自己翻记录整理？** 决策散落在消息里，下次继续时又要重新交代。

Talk to Plan 帮你先看全局，留出边问边想的空间，再随着你逐块拍板，把共识整理成可继续维护的文档。

## 怎么使用

1. **先看全局。** AI 梳理整体架构，提出值得讨论的议题。
2. **按你的节奏聊。** 你选择话题，AI 负责解答、调查和建议。
3. **拍板后再记录。** 只有你明确认可，AI 才会把结论写入文档。

可以跳过话题、推翻想法，也可以把细节留到以后。“明白了”“有道理”不会被当成定案。

## 安装

需要 Node.js 和 npm，运行后选择你的 AI 工具：

```bash
npx skills add WT006/talk-to-plan-skill --skill talk-to-plan
```

## 开始讨论

在 Codex 中输入：

```text
$talk-to-plan 先给我整体架构和几个值得讨论的模块。
我们逐块探讨，我明确拍板后再把结论整理到文档中。
```

之后自然交流即可，不必每轮重复技能名。此 skill 在 Codex 中开发，指令使用中文，也可以要求 AI 用其他语言讨论。

## 简单举例

> **你：** $talk-to-plan 我想做一个收藏工具，先帮我看看整体怎么设计。
>
> **AI：** 可以先讨论内容收集、分类检索和多端同步这几块，它们之间的关系是……
>
> **你：** 先聊同步吧。第一版一定要做吗？我想简单一点。
>
> **AI：** 如果你先在一台设备上使用，我建议第一版只做本地保存。范围更小，但暂时无法在其他设备上查看收藏。
>
> **你：** 就先做本地保存，同步以后再设计。把这个记下来。
>
> **AI：** 已把决定、取舍和暂缓的同步议题写入设计文档。接下来可以聊内容收集或分类检索。
